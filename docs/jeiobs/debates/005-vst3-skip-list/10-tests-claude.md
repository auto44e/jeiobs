## Doubts
- **Where the spec was silent, the tests assume the following**, and the implementation must match or the lead must adjust the tests:
  - **File locations:** `vst3skip.json` and `vst3scan.lock` sit in the directory of the list path given as `argv[1]`.
  - **Remembered line:** exactly `Skipped <path>: remembered <reason> (Rescan to retry)`. Hang lines keep `probe timed out` / `probe timed out (killed)`.
  - **`VST3_SKIPPED`:** printed on every finished scan, also when it is 0. Its value is only checked in scans where every skip is a remembered one, since it's unclear whether it also counts fresh failures.
  - **Entry fields:**
    - `binary` is absolute, or relative to the bundle.
    - `size` is the file size.
    - `crc32` is the standard zlib CRC-32, stored as an integer (hex or decimal strings are accepted).
    - `failures` goes up by 1 for each failure with the same fingerprint (a crash after Rescan gives 2). It resets to 1 when the binary changes and is kept when only the version changes.
    - `obs_version` is a non-empty string.
  - **Times:** `retry_after` and `last_failed` are integers in the same unit, and `retry_after − last_failed` is 7 days (seconds, ms, µs, 100 ns or ns, ±120 s). "In the past" is done by setting `retry_after` to `last_failed − 7 d`.
  - **Torn skip file with a valid `.bak`:** the `.bak` is used, so the bundle is not probed.
  - **Stale files:** the tests plant `probe-*.json.status` and `vst3list.json.tmp-<pid>`, both older than 1 h. The status file's own temp name isn't in the spec, so I didn't plant it.
  - **Blocked scanner:** a scanner waiting on the lock must change nothing in the cache dir. That includes the old `probe-*.json(.tmp)` cleanup from task 003, so `removeStaleProbeResults()` has to run under the lock. This is a strict reading of "temp files unchanged".
- **Timing margins:**
  - Lock-held check: the lock is held for 4 s and sampled at 1 s, leaving about 2.9 s of slack. It passes or fails on ordering (the holder ended before the scan did), not a duration threshold.
  - Cancel check: the scanner must open the lock within 3 s, then gets 0.5 s to confirm it's waiting, under a 10 s hold.
  - Orphan check: the probe timeout is 10 s (the scanner's own kill comes at 15 s) and the steps take under 1 s. The freeze window is 3 s.
  - Every check passed while 7 model suites ran in parallel. The new section takes about 25 s, about 2.1 s per hang scan.
- **Root:** as root, #6 prints a `SKIP` line instead of running, because the process limit (`ulimit -u`) doesn't apply to root. The exit status is unaffected; the lead should decide whether a SKIP should fail a gate, for example in a clean-room container running as root.
- **`ulimit -u 1` also blocks threads.** If the D6 scanner starts a thread before it spawns probes, #6 will report the scan itself failing.
- **Orphan check:** it uses `timeout --foreground`, so the stopped orphan gets no SIGHUP when its scanner dies. Observed here: the orphan was re-parented to PID 9069 and stayed stopped.
- **Not covered:** 30-day `missing_since` pruning, the fallback when no lock is available (ENOLCK → `tmp-<pid>`), unknown file versions or malformed entries, Windows and macOS, and the host side (Rescan passing `--retry-failed`, the warning text). Nothing was run as root or against the real implementation.
